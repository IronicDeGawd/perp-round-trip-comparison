DreamDEX · Somnia

One transaction vs two orders

A bot opens and closes a BTC perpetual on two venues. We time each to on-chain settlement — not to an API acknowledgement — from the same cloud box next to both.

On DreamDEX the open and the close go in one atomic on-chain transaction. The wallet is delegated (EIP-7702) to a small batcher contract, and a single transaction places both orders against the pool's on-chain order book. Either both fills land or neither does.

On Hyperliquid the open and the close are two separate signed orders. Each is a signed message sent to Hyperliquid's API server and matched on HyperCore, its own order-book chain. They settle as two independent steps.

Honest notes

  • This is a capability story, not a gas story. On Somnia the EIP-7702 authorization costs ~1.57M gas (far more than on Ethereum), so the atomic batch saves nothing on gas versus two transactions. The point is atomicity — one all-or-nothing transaction — and self-custody, not cost.
  • Hyperliquid's ~700 ms per order is real on-chain settlement, not an off-chain trick. A read from the same box was ~9 ms, so the ~700 ms is genuine HyperCore consensus for a write. The honest distinction is shape: Hyperliquid has no single atomic on-chain open-and-close — orders settle as separate steps.
  • Location matters. The same DreamDEX round-trip measured from a laptop over the public internet read ~1.4 s — all network round-trip. The numbers here are from a server next to the venues; reproduce from there or expect inflation.

Reproduce it

Testnet only. The repo holds a committed sample run, so the race UI replays with no setup; running live needs a funded DreamDEX throwaway wallet and a Hyperliquid testnet agent.

npm install
cp .env.example .env     # three testnet credentials
npm run setup            # DreamDEX: approve margin, deposit, attach 7702
npm run race             # serves the UI at http://localhost:8800

Open the UI and press Run both. Each run is saved as a JSON timeline with its tx hashes, which the UI can replay deterministically.

Every number on screen is measured; the tx hashes are real HyperCore and Hideki hashes. Code and method: github.com/IronicDeGawd/dreamdex-vs-hyperliquid.
